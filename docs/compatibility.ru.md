# Совместимость TeamForge

Страница описывает **границы совместимости и топологии для читателя**.

- Точные версии продукта/runtime/протокола → [`../release-contract.json`](../release-contract.json)
- Текущая проверка/готовность → [STATUS.md](STATUS.md) (английский)
- Идентичность пакета → [`../builds/README.md`](../builds/README.md) + точный SHA-256 Release

Не дублируйте быстро меняющиеся номера патчей инструментов/runtime: ими управляет контракт выпуска.

## Перед проверкой

Используйте ненужный тестовый проект и резервные копии. TeamForge — ранняя публичная предварительная версия; [STATUS.md](STATUS.md) определяет границы полевых проверок. Матрица отделяет целевую платформу пакета от требований исходников/сборки.

Минимальные требования CPU, RAM, GPU, диска, пропускной способности и задержки ещё не установлены контролируемыми испытаниями. Успешный запуск прототипа не является рекомендацией минимального оборудования.

Guest должен иметь доступ к настроенному Server и адресу Project Peer, объявленному Host. Подписанное приглашение не обеспечивает сетевую доступность. Используйте один компьютер, доступную LAN или управляемую VPN; автоматический обход сетевых препятствий Интернета и relay не предоставляются.

## Продукт и протокол

Компоненты развиваются как совместимая линейка, а не произвольная смесь версий Server/Project Peer/Launcher/пакета. Архитектура разделяет:

- полномочия совместной работы в реальном времени через WebSocket настроенного Server;
- координацию начальной загрузки проекта и метаданных;
- прямую передачу данных Project Peer;
- целостность упакованных Host/Guest Runtime и Launcher.

Изменения протокола/схемы аддитивны лишь при совместимости прежней семантики. Точные номера — в `release-contract.json`. Не смешивайте манифесты или бинарные файлы Runtime/Launcher разных кандидатов только из-за одинаковой видимой версии.

## Unity

Текущая поддерживаемая линейка — **Unity 6000.3**. Патч Editor считается проверенным только при наличии записанных доказательств для нужного исходного кода/кандидата. Новейший патч Unity не становится автоматически проверенным или поддерживаемым. Выбор проверенного Editor хранится в `release-contract.json`, доказательства — в [STATUS.md](STATUS.md).

## Разработчики и runtime

Используйте диапазоны Node/npm/.NET/инструментов из контракта и конфигурации lock/build репозитория. Это **требования исходников/сборки**, не обычной установки упакованного Host/Guest, использующей встроенные/автономные runtime согласно контракту. Новое основное семейство runtime/toolchain требует осознанного решения и проверки совместимости; одной успешной установки недостаточно.

## Поддерживаемая топология

- настроенный WebSocket Server TeamForge для полномочий реального времени;
- прямой HTTP Project Peer на одном PC, доступной LAN или управляемой VPN;
- явный режим одного PC только через loopback;
- аутентифицированное прослушивание вне loopback с конкретным адресом для Guest;
- упакованный Windows Host/Guest с проверенным встроенным Runtime.

Сейчас не предоставляются как поддерживаемая топология: WebRTC / RTCDataChannel; ICE / STUN / TURN; автоматический обход NAT; relay/автоматический резервный транспорт; обнаружение peer; бессерверные/встроенные полномочия реального времени; развёртывание в недоверенном публичном Интернете с полной системой идентификации и авторизации пользователей.

`P2P` означает **прямую передачу данных Project Peer**, а не автоматическую P2P-связь через Интернет.

## Матрица платформ

| Область | Состояние |
| --- | --- |
| Встроенный Runtime Windows x64 / Guest Launcher | Текущая целевая платформа пакета; конкретный кандидат подчиняется полевым критериям STATUS |
| Unity 6000.3 | Текущая линейка Unity |
| Записанный точный патч Unity | `release-contract.json` и доказательства STATUS |
| Другие патчи Unity 6000.3 | Отдельная перебазировка/проверка до заявления о тестировании |
| Автономный Launcher macOS/Linux | Нет эквивалентного текущего упакованного кандидата |
| Docker/Compose | Вариант исходников/сервера, не обычный упакованный Host и не текущий критерий выпуска |
| Authenticode | Статус распространения/подписи — в STATUS/документации артефакта |

## Управляемое хранилище Windows в текущем коде

Текущий код требует локальный корень на фиксированном диске NTFS/ReFS для блокировки идентичности проекта Windows. Сетевые, недоступные или непроверенные корни отклоняются по принципу fail-closed. Это условие хранилища TeamForge, не общее требование Unity. Граница исходники/опубликованный кандидат описана в [STATUS.md](STATUS.md); см. [реализацию](../project-peer/src/project-identity-lock.mjs).

## Заявления и история

Исторические отчёты фаз/работ/тестов относятся к записанному коду/артефакту. Похожая версия не делает их текущими доказательствами. Для идентичности байтов используйте имя файла Release + SHA-256, а не только версию.
