# TeamForge の互換性

このページは**互換性とネットワーク構成の境界**を説明します。

- 現在の製品・ランタイム・プロトコルの正確な選択値 → [`../release-contract.json`](../release-contract.json)
- 現在の検証状況と準備状況 → [STATUS.md](STATUS.md)
- パッケージ成果物の識別 → [`../builds/README.md`](../builds/README.md) + 対象 Release の正確な SHA-256

頻繁に変わるツールやランタイムのパッチ番号を複数の文書にコピーしないでください。正確な選択値はリリース契約が管理します。

## テストの前に

破棄できるテスト用プロジェクトを使い、バックアップを残してください。TeamForge は初期公開プレビューです。現在の実環境での検証範囲は [STATUS.md](STATUS.md) が管理します。下のプラットフォーム表は、パッケージの対象とソース・ビルドの要件を区別しています。

CPU、RAM、GPU、ディスク、帯域幅、遅延の最低要件は、まだ統制されたテストで確立されていません。プロトタイプが動いたことは、最低ハードウェア構成を推奨する根拠にはなりません。

Guest は、設定された Server と Host が通知する Project Peer エンドポイントに到達できる必要があります。署名付き招待だけではネットワーク経路は作られません。同じコンピューター、到達可能な LAN、または管理された VPN を使ってください。インターネットの自動トラバーサルやリレーは提供されません。

## 製品・プロトコルの互換性

TeamForge の各構成要素は、Server・Project Peer・Launcher・パッケージのバージョンを独立に混在させず、互換性のある一つの製品系列として更新することを意図しています。

現在のアーキテクチャは次を分離しています。

- 設定された TeamForge Server WebSocket によるリアルタイム共同作業の権限管理
- プロジェクトの初期準備とメタデータの調整
- Project Peer 間の直接ペイロード転送
- パッケージの Host/Guest Runtime と Launcher の完全性

プロトコル・スキーマのバージョン互換性を追加拡張として扱えるのは、既存の意味が互換のまま保たれる場合だけです。正確な選択番号は `release-contract.json` が管理します。

表示される製品バージョンが同じでも、異なるパッケージ候補から生成された Runtime/Launcher のマニフェストやバイナリを混在させないでください。

## Unity の互換性

現在サポート対象となる Unity 製品系列は **Unity 6000.3** です。

特定の Editor パッチを検証済みとするには、対象ソース・候補について記録された証拠が必要です。上流の最新 Unity パッチを自動的にテスト済み・サポート対象と見なさないでください。

テスト記録にある正確な Editor の選択値は `release-contract.json` にあり、現在の証拠は [STATUS.md](STATUS.md) にまとめられています。

## 開発・ランタイムの互換性

ソース開発者は `release-contract.json` とリポジトリのロック・ビルド設定が選択する Node/npm/.NET/ツールの範囲を使用してください。

これは**ソース・ビルド要件**であり、パッケージ Host/Guest 経路の一般利用者向けインストール要件ではありません。後者は現在のリリース契約に従い、同梱または自己完結型のランタイム構成要素を使います。

新しいメジャー Runtime・ツールチェーン系列は、一台でインストールできたことから互換性を推測せず、明示的な判断と検証を行う必要があります。

## サポートする構成

現在サポートまたは意図している構成は次のとおりです。

- リアルタイム権限管理のために設定された TeamForge Server WebSocket
- 同じ PC、到達可能な LAN、管理された VPN 上の直接 Project Peer HTTP 転送
- 明示的なループバック専用の同一 PC モード
- 認証付きの非ループバック待ち受けと、Guest に通知する具体的なホスト
- 検証済みの同梱 Runtime を使うパッケージ Windows Host/Guest の流れ

現在サポートする構成として提供されていないもの：

- WebRTC / RTCDataChannel
- ICE / STUN / TURN
- 自動 NAT トラバーサル
- リレー / 自動トランスポートフォールバック
- 自動ピア検出
- サーバーレス・内蔵のリアルタイム権限管理
- 完全なユーザー識別・認可システムを備えた、信頼されない公開インターネットへの配備

現在の TeamForge 文書で `P2P` は**直接 Project Peer ペイロード転送**を意味し、インターネット上の自動 P2P 接続を意味しません。

## プラットフォーム表

| 対象 | 互換性の状況 |
| --- | --- |
| Windows x64 同梱 Runtime / Guest Launcher | 現在のパッケージ対象。個別候補は引き続き STATUS の実環境検証条件に従う |
| Unity 6000.3 | 現在の Unity 製品系列 |
| 記録された正確な Unity パッチ | `release-contract.json` + STATUS の証拠を参照 |
| その他の Unity 6000.3 パッチ | テスト済みとする前に個別のベースライン再設定・検証が必要 |
| macOS/Linux 単体 Launcher | 現在の同等候補としてはパッケージ化されていない |
| Docker/Compose | ソース・サーバーの選択肢。通常のパッケージ Host 経路や現在のリリース条件ではない |
| Authenticode | 配布・署名状況は STATUS と現在の成果物文書が管理 |

## 現在のソースにおける Windows 管理ストレージ

現在のソースでは、Windows のプロジェクト識別ロックにローカル固定 NTFS/ReFS 管理ルートが必要です。ネットワーク上、利用不可、または未確認のルートは拒否します。これは TeamForge の管理ストレージの条件であり、一般的な Unity プロジェクトの新たな要件ではありません。ソースと公開候補の境界は [STATUS.md](STATUS.md)、実装は[担当ソース](../project-peer/src/project-identity-lock.mjs)を参照してください。

## 互換性の主張と履歴

過去のフェーズ・作業・テスト報告は、記録されたソース・成果物に適用されます。表示バージョンが現在の系列に似ているだけで、現在の互換性の証拠にはできません。

正確なバイト単位の識別が重要な場合は、製品バージョンだけでなく Release アセットのファイル名 + SHA-256 を使ってください。
