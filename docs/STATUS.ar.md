> **معاينة عامة مبكرة — لا تستخدم TeamForge بوصفه النسخة الوحيدة أو آلية الاسترداد الوحيدة لمشروع Unity مهم.** خضعت عوائق Windows WP5.1 الأصلية لاختبارات مادية واسعة على r5 نفسه، لكن `main` أحدث ويضم سلوكًا إضافيًا للشبكات والهوية لم يُختبر بعد مجتمعًا في حزمة بديلة محددة على أجهزة PC فعلية. احتفظ بنسخ احتياطية وفضّل مشاريع اختبار يمكن الاستغناء عنها.

## المصدر مقابل الحزمة المنشورة

دُمجت إصلاحات WP5.1 الأصلية للمشكلات #67 و#68/#74 و#69 و#70 و#71 عبر PR #81. أُنتج r5 من commit المذكور ويضم هذه الإصلاحات وتكامل Launcher **Save support bundle** المضاف بعد r4.

في 2026-08-31 اختُبر r5 نفسه على جهازي Windows فعليين: إعادة اتصال Guest بعد الحفظ، وانضمام Guest جديد متأخرًا مع لقطة Transform، وقطع الاستقبال واستئنافه مرارًا، وتسليم المسارات الطويلة/العميقة عبر execution alias، والتعافي من تعارض محمي نتج عن حالة قديمة لتنافس lock. وبعد توفير إذن جدار الحماية المطلوب، تحقق الاختبار المادي أيضًا من Host Stop/Start وإعادة ربط Seed TCP `5091` ونقل Project حقيقي إلى Guest.

لم تعد هذه السيناريوهات تنتظر أول إعادة اختبار مادي لـ r5. لا يجعل ذلك تغييرات المصدر اللاحقة جزءًا من r5، ولا يجعل المنتج alpha قابلة للتثبيت عمومًا. استخدم r5 وأدلة 2026-08-31 عند وصف الحزمة؛ لا تصف r5 بأنه مكافئ لـ `main` في البايتات أو السلوك. لا تُعد السيناريوهات المغلقة إلى قائمة الانتظار لمجرد بقاء نص قديم. إذا اختير `main` للتوزيع، فيلزم نشر مرشح جديد غير قابل للتغيير واختبار السلوك المضاف بعد r5 على ذلك الملف المحدد.

## تحسينات لاحقة غير موجودة في r5

- يستطيع إعداد جدار حماية Windows LAN إنشاء قواعد واردة ضيقة لـ Coordinator/Seed بعد موافقة صريحة من المستخدم وUAC، محصورة في ملف Private وLocalSubnet، مع تسوية وتنظيف القواعد المملوكة لـ TeamForge. كان اختبار r5 يحتاج إذنًا يدويًا؛ المسار الجديد يحتاج دليلًا ماديًا على الحزمة المحددة.
- عند انشغال منفذ Seed المفضل/الافتراضي أو تعذره، بما في ذلك `EACCES` في سياق bind على Windows، يعيد Host المحاولة مرة واحدة بمنفذ يخصصه نظام التشغيل ويعلن نقطة النهاية المختارة. توجد اختبارات Windows Project Peer آلية، لكن السلوك أحدث من r5.
- تسلسل إنشاء هوية Project والتعافي من تعطل Windows عبر قفل حي named-pipe يملكه نظام التشغيل وحاجز توافق دائم للبرامج الكاتبة الأقدم. نجحت مجموعات اختبارات التعطل/التزامن على Windows Node 22/24؛ لا توجد حزمة منشورة تتضمن التغيير ولديها دليل ميداني مادي مطابق.
- تنظيف رفض Coordinator، وتحسين إلغاء HTTP ومهله، وسياق تشخيص Host، وسجلات أدوار عملاء WebSocket، والتمييز الأوضح بين دعوات Launcher ورموز الاتصال `TF1`.

هذه حقائق عن المصدر/الأتمتة، وليست سلوك حزمة r5. كما أن استرداد أقفال هوية Project القديمة على Linux/macOS خارج هذا التغيير الخاص بـ Windows.

## الأدلة الآلية والمحلية

قبل دمج PR #81 اجتاز head المتكامل النهائي البوابات المسجلة في `docs/MAIN_PATCH_STATUS_2026-08-27.md`:

- CI #216: Server وProject Peer ومحمل Runtime Launcher وWindows Launcher وعقد المصدر العام **PASS**.
- Dependency Review #140 **PASS**.
- Unity Tests #73: Unity Lock Contention E2E وUnity Realtime Authority E2E وRealtime Authority Chaos E2E وProject Transfer Resume E2E **PASS**.
- Unity Test Runner المحلي السابق: **143/143 اختبارًا قابلًا للتشغيل محليًا PASS**؛ تُرك عمدًا اختباران بخادم حقيقي مخصصان لـ CI دون تشغيل محلي.
- تعافي تنافس A/B على الجهاز نفسه **PASS**؛ تقارب Hierarchy/Transform مع انضمام A/B/C المتأخر **PASS**، دون تعارضات محمية في التشغيل المسجل.

جُرّبت التحسينات اللاحقة باختبارات مركزة لـ Project Peer/Launcher/Unity وبوابات الجودة المعتادة. نجحت مجموعة هوية Windows على خطي Node 22/24 المدعومين؛ ونجح انحدار منفذ Seed المتعذر ضمن مجموعة Project Peer الكاملة في بيئة Windows المعاد إنتاجها. يعزز ذلك الثقة بالمصدر، ولا ينشئ دليل حزمة لبايتات نُشرت قبل الإصلاحات.

## أدلة جهازين فعليين

المسار الأساسي 2026-08-22: Host → دعوة موقعة → Guest جديد → مصادقة → نقل مباشر → ثقة Publisher → Active متحقق → اتصال Unity realtime؛ Presence وTransform باتجاهين؛ تنافس lock عادي؛ إنشاء/تسمية/تغيير أصل/ترتيب أشقاء/حذف في Scene واحدة. خروج Guest دون حفظ وإعادة فتحه استعاد Hierarchy/Transform/Lock من الجلسة التي بقيت تعمل. انقطاع TCP Coordinator → retry → اتصال تلقائي دون إعادة تشغيل Unity.

في 2026-08-31 أغلق زوج ZIP/SHA المحدد لـ r5 السيناريوهات المستهدفة على جهازي Windows فعليين. نجح كذلك Seed `5091` Stop/Start ونقل LAN حقيقي؛ ظل إذن الجدار الأولي يدويًا حينها.

## حدود الأدلة

النتيجة تثبت ما اختُبر فقط. CI المصدر لا يثبت صحة ZIP. أتمتة Unity لا تعيد كل ترتيب إدخال SceneView أو حالة عمليات Windows أو LAN/الجدار أو توقيت الجهاز الثاني. اختبار الجهاز الواحد يشترك في OS ومكدس الشبكة والبيئة الزمنية والعتاد. دليل r5 لا يثبت `main` اللاحق. رقم الإصدار ليس هوية بايتات؛ يلزم اسم الملف وSHA-256 المحددان. إغلاق خطأ لا يمنح تغييرات النظام الفرعي اللاحقة دليل حزمة/ميدان تلقائيًا. السجلات التاريخية صالحة للقطة وقتها ولا تتجاوز STATUS الحالي.

## شروط الإصدار المتبقية

قبل تقديم TeamForge بوصفه alpha قابلة للتثبيت عمومًا:

1. الاحتفاظ بإغلاقات r5 المادية #67/#68/#69/#71/#74 باعتبارها مكتملة.
2. إذا وُزّع `main`، نشر مرشح جديد غير قابل للتغيير.
3. اختبار إعداد الجدار الجديد، ونطاق القواعد الضيق ودورة حياتها، وبديل المنفذ المفضل المشغول/المتعذر، والوصول الحقيقي إلى Seed المعلن، وHost Stop/Start، ونقل Guest جديد على الحزمة البديلة المحددة.
4. اختبار تعافي هوية Windows بعد فقدان العملية، وإعادة التشغيل الآمنة، واستمرار fail-closed للهويات المبهمة/المتعارضة على الملف نفسه.
5. إجراء smoke من Host مفكوك حديثًا → Guest جديد → تعاون realtime على البديل، دون افتراض وراثة أدلة r5.
6. حفظ الاسم/SHA/هوية المصدر الدقيقة وتسجيل السيناريوهات المنفذة فقط.
7. مواصلة إرشادات التثبيت/التحديث/الإزالة والحصول على اختبارات ومراجعات من غير منشئ المشروع قبل ادعاءات موثوقية واسعة.

إعادة تشغيل عملية الخادم حاليًا هي **قطع اتصال/fail-closed/تعافٍ بجلسة جديدة**، وليست اختبار استمرارية تخزين: لم يُنفذ التعافي الدائم لـ authority/session بعد إعادة التشغيل.
