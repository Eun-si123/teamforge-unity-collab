# P1 M4→M5: Coordinator online multi-Editor pause/ACK admission — 2026-11-24

**Integration:** Draft PR #620. **Product state: `FIELD_BLOCKED`.** This builds an opt-in, internal server-side ACK gate; it does **not** implement actual Unity Editor write suspension/asset save, cross-store commit or client-ready rollout. The existing offline guard and signed Publisher possession proof remain intact.

## Missing prerequisite and scope

A durable M4 Session can contain multiple online Editors and saved Component/Hierarchy/Transform work. Checking only the Host/Publisher's signed M5 file cannot prove that those Editors have stopped creating new commands, drained their in-flight requests, saved/verified local Unity Scenes/assets or can safely switch Guest Active content. The original implementation correctly refused *all connected Editors* in `tryBeginOfflineProjectFreeze`, but provided no transport preparation mechanism for future explicit Editor pause and ACK.

## Implemented in the Node Coordinator

- `ProjectTransitionQuiescence.beginOnlinePause`: an **internal-only** request, not a remotely callable WebSocket command. Requires a healthy durable Coordinator, same signed old M4 Baseline, every currently registered Project Editor offering the new opt-in capability, exact current Session epochs/lineages/revisions, a complete Project Editor roster, **no active locks** and **no outstanding async signed source admissions**. Freeze installs synchronously *before* sending any pause notice. Old offline freeze remains available only for empty Projects.
- An opt-in `supportsProjectEditPause` Hello field (default absent/false), validated against durable Editor, Presence, Hierarchy/Transform and Project Transfer capabilities. For opted-in connections, `hello_ack` adds `projectEditPauseEnabled` with negotiated status. **The shipping Unity Editor does not yet offer this capability**, so it cannot be mistaken for a safely pausable client.
- Server sends `project_edit_pause_request` with unique unpredictable pause UUID, exact signed old Baseline hashes and revision, one Editor's authority epoch, durable Session ID, saved server revision and bounded deadline. While the pause is pending, ALL project-changing and state-affecting WebSocket messages are refused (including reconnect Hello, lock, Hierarchy, Transform, Component, Project Seed/Publisher messages) except `ping` and exact `project_edit_pause_ack`. Unrelated Projects continue normally.
- Editor ACK schema is closed to unknown fields. Each ACK is scoped to the *actual authenticated WebSocket connection*, matching pause UUID and current server-owned Session revision/epoch/lineage; only `status=ready` counts positively, and `busy` or a changed Session cursor aborts the whole pause. Duplicates and replay from other connections are rejected, rather than counted twice. A confirmed ACK **is an Editor assertion**, not proof of on-disk local Scene/Asset quiescence.
- A positive gate requires **all** currently participating Editors, not one. The internal result always has `commitPermitted:false`; the Coordinator exposes no online ticket externally. An Editor disconnect, an explicit busy ACK, a stale cursor, local operator cancel or an expired deadline drops the whole in-memory pause and broadcasts `project_edit_pause_cancelled`. The freeze is not persisted over restart. Public Unity Editor does not have pause ACK behavior and normal TeamForge activity remains unaffected.
- A new `project_edit_pause_acknowledged` receipt only reports the number of Editors that acknowledged and explicitly states `commitPermitted:false`. It never updates Host `published.json`, SQLite M4/M5 checkpoint journals, signed source pointers or Guest Active versions.

## Test evidence

- Actual real WebSocket two-Editor test: signed M4 baseline published; two explicitly opted-in simulated Editor clients join the same saved Session. The server installs the barrier, refuses a late Editor and a native Hierarchy seed, receives valid ACK 1/2 (`ready=false`), then ACK 2/2 (`ready=true` but `commitPermitted=false`). Explicit cancel sends both Editors a cancelled event, and subsequent original M4 native Cube/Collider creation succeeds.
- Separate real WebSocket test rejects a `busy` ACK, cancels when an Editor disconnects, and refuses a stale replayed ACK. A single legacy/non-opted-in Editor makes the entire initiation fail before sending any pause frame. Two Editor connections in **different durable Sessions** have different epochs and lineages; using the other Editor's matching signed Project and valid Session cursor cannot trick the server into accepting the wrong Editor's ACK.
- In-process tests reject missing/duplicated editor roster, active lock, pending async admissions, stale epochs/revisions, duplicate ACKs, timeout and partial editor loss. No unknown Editor may append an ACK or borrow another connection's cursor.
- Final Ubuntu Mini PC Node 24 validation: **Server 492 PASS / 0 FAIL**, **Project Peer 651 PASS / 0 FAIL / 6 environment SKIP** (657 total), **cross-Phase 153 PASS / 0 FAIL**; test sets overlap. Initial *simultaneous* Project Peer/cross-Phase runs encountered host startup/timeout failures under high shared load, so they were not treated as passing. **Both suites passed on sequential rerun.** The separately added, different-durable-Session Editor ACK regression also passed; the final Server run includes it. Engineering, workflow, documentation and public-source validators, smoke and fresh GitHub CI are recorded independently. **Not performed:** Unity Editor 2-PC end-to-end, real local write-stop/save ACK, Host/Guest promotion/rollback, real power-cut or packaged release ZIP tests.

## Next gate before any live commit

The Unity Editor must stop emitting new Hierarchy/Transform/Collider/etc. commands, retain locally changed native Scene/Asset edits, handle in-flight operation results and Undo/redo, and return an honest `ready` only after all pending work and saved local state are independently verified. A timeout, editor crash or reconnect needs a safe resume/recovery copy rather than silent discard. Publisher key possession, exact signed staged source bytes and all Guest Active acknowledgments are then separate gates. This milestone does **not** authorize any live Baseline migration or release.
