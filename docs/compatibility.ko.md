# TeamForge 호환성

이 문서는 **호환성과 네트워크 구성의 범위**를 설명합니다.

- 현재 제품·런타임·프로토콜의 정확한 선택 값 → [`../release-contract.json`](../release-contract.json)
- 현재 검증 상태와 준비도 → [STATUS.md](STATUS.md)
- 패키지 산출물의 식별 정보 → [`../builds/README.md`](../builds/README.md) + 해당 Release의 정확한 SHA-256

자주 바뀌는 도구·런타임 패치 번호를 여러 문서에 복사하지 마세요. 정확한 선택 값은 릴리스 계약에서 관리합니다.

## 테스트하기 전에

버려도 되는 테스트용 프로젝트를 사용하고 백업을 유지하세요. TeamForge는 초기 공개 프리뷰이며, 현재 실제 환경 검증 범위는 [STATUS.md](STATUS.md)에서 관리합니다. 아래 플랫폼 표는 패키지 대상과 소스·빌드 요구사항을 구분합니다.

최소 CPU, RAM, GPU, 디스크, 대역폭, 지연 시간 요구사항은 아직 통제된 테스트로 정해지지 않았습니다. 프로토타입이 한 번 실행됐다고 최소 하드웨어를 권장할 근거가 되지는 않습니다.

Guest는 설정된 Server와 Host가 알린 Project Peer 엔드포인트에 접속할 수 있어야 합니다. 서명된 초대가 네트워크 연결 경로를 만들어 주지는 않습니다. 같은 컴퓨터, 서로 접속 가능한 LAN 또는 관리형 VPN을 사용하세요. 자동 인터넷 연결 설정과 릴레이는 제공하지 않습니다.

## 제품·프로토콜 호환성

TeamForge 구성 요소는 Server·Project Peer·Launcher·패키지 버전을 제각각 섞기보다, 서로 호환되는 하나의 제품 계열로 함께 업데이트하도록 설계되어 있습니다.

현재 구조는 다음을 구분합니다.

- 설정된 TeamForge Server WebSocket을 통한 실시간 협업 권한 관리
- 프로젝트 참가 준비와 메타데이터 조율
- Project Peer 간 직접 데이터 전송
- 패키지에 포함된 Host/Guest Runtime과 Launcher의 무결성

프로토콜·스키마 버전 호환성은 기존 의미가 유지될 때만 추가 확장으로 취급합니다. 선택된 정확한 프로토콜·스키마 번호는 `release-contract.json`에서 관리합니다.

표시된 제품 버전이 같더라도 서로 다른 패키지 후보의 생성된 Runtime/Launcher 매니페스트나 바이너리를 섞지 마세요.

## Unity 호환성

현재 지원하는 Unity 제품 계열은 **Unity 6000.3**입니다.

특정 Editor 패치를 검증했다고 말하려면 해당 소스·후보를 대상으로 기록된 증거가 있어야 합니다. Unity의 최신 패치라는 이유만으로 자동으로 테스트되거나 지원된다고 간주하지 마세요.

실제 테스트에 기록된 정확한 Editor 선택 값은 `release-contract.json`에 있으며, 현재 증거는 [STATUS.md](STATUS.md)에 요약되어 있습니다.

## 개발·런타임 호환성

소스 개발자는 `release-contract.json`과 저장소의 잠금·빌드 설정에서 지정한 Node/npm/.NET/도구 범위를 사용해야 합니다.

이는 **소스·빌드 요구사항**입니다. 현재 릴리스 계약에 따라 번들·자체 포함 런타임 구성 요소를 사용하는 패키지 Host/Guest 경로의 일반 사용자 설치 요구사항이 아닙니다.

새로운 메이저 Runtime·도구 체계는 한 컴퓨터에서 설치에 성공했다는 사실로 호환성을 추정하지 말고, 별도 호환성 결정과 검증을 거쳐야 합니다.

## 지원하는 네트워크 구성

현재 지원하거나 의도한 구성은 다음과 같습니다.

- 실시간 권한 관리를 위한 설정된 TeamForge Server WebSocket
- 같은 PC, 접속 가능한 LAN 또는 관리형 VPN에서의 직접 Project Peer HTTP 전송
- 명시적인 루프백 전용 동일 PC 모드
- 구체적인 Guest 접속 대상 호스트를 알리는, 인증이 적용된 비루프백 수신
- 검증된 번들 Runtime을 사용하는 패키지 Windows Host/Guest 흐름

현재 지원 구성으로 제공하지 않는 항목:

- WebRTC / RTCDataChannel
- ICE / STUN / TURN
- 자동 NAT 통과
- 릴레이 / 자동 전송 방식 전환
- 자동 피어 검색
- 서버리스·내장 실시간 권한 관리
- 완전한 사용자 신원·권한 부여 체계를 갖춘 비신뢰 공개 인터넷 배포

현재 TeamForge 문서의 `P2P`는 **Project Peer 간 직접 데이터 전송**을 뜻하며, 인터넷에서 자동으로 연결되는 P2P를 뜻하지 않습니다.

## 플랫폼 표

| 항목 | 호환성 상태 |
| --- | --- |
| Windows x64 번들 Runtime / Guest Launcher | 현재 패키지 플랫폼 방향. 정확한 후보는 여전히 STATUS의 실제 환경 검증 조건을 따름 |
| Unity 6000.3 | 현재 Unity 제품 계열 |
| 테스트에 기록된 정확한 Unity 패치 | `release-contract.json` + STATUS의 증거 참고 |
| 다른 Unity 6000.3 패치 | 테스트됐다고 말하기 전에 별도 기준 재설정·검증 필요 |
| macOS/Linux 독립형 Launcher | 동등한 현재 후보로 패키징되어 있지 않음 |
| Docker/Compose | 소스·서버 선택지. 일반적인 패키지 Host 경로나 현재 릴리스 조건은 아님 |
| Authenticode | 배포·서명 상태는 STATUS와 현재 산출물 문서에서 관리 |

## 현재 소스의 Windows 관리 저장소

현재 소스는 Windows 프로젝트 정체성 잠금을 위해 로컬 고정 NTFS/ReFS 관리 루트를 요구합니다. 네트워크 경로, 사용할 수 없거나 확인되지 않은 루트는 허용하지 않습니다. 이는 TeamForge의 관리 저장소 조건이며, 일반 Unity 프로젝트에 새로 부과되는 요구사항은 아닙니다. 소스와 공개 후보의 차이는 [STATUS.md](STATUS.md), 구현은 [담당 소스](../project-peer/src/project-identity-lock.mjs)를 확인하세요.

## 호환성 주장과 과거 기록

과거 단계·작업·테스트 보고서는 당시 기록한 소스·산출물에 적용됩니다. 표시된 제품 버전이 현재 계열과 비슷하다는 이유로 현재 호환성의 증거로 사용하면 안 됩니다.

정확한 바이트 식별이 필요할 때는 제품 버전만 보지 말고 Release 자산 파일명 + SHA-256을 사용하세요.
