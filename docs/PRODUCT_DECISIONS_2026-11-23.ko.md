# TeamForge — 사용자 인터뷰 기반 제품 결정 (2026-11-23)

> 이 문서는 **개발 방향과 완료 기준**입니다. 여기 적힌 기능이 구현되었다는 뜻이 아닙니다. 정확한 기능·검증·배포 상태는 [STATUS.ko.md](STATUS.ko.md), 단계별 기술 로드맵은 [ROADMAP.ko.md](ROADMAP.ko.md)를 확인하세요. 상세한 개발자용 계약과 테스트 기준은 [영문 제품 명세](PRODUCT_DECISIONS_2026-11-23.md)에 있습니다.

## 한 문장 목표

**평소 쓰던 Unity Editor 그대로 여러 사람이 함께 게임을 만들고, 충돌·연결 끊김·호스트 종료가 생겨도 각자의 작업을 안전하게 보존하는 협업 도구.** AI 에이전트는 검증된 Unity CLI/MCP 연결과 별도 권한 조건이 충족될 때 참여할 수 있습니다.

**우선순위:** 작업물 손실 방지 → 정확한 동기화와 복구 → 쉬운 설치·초대·상태 안내 → 측정된 성능/호환성 → Unity 기능 확장.

## 사용자 인터뷰 Q1~Q13의 잠정 결론

| 구분 | 목표 | 반드시 구분할 것 |
| --- | --- | --- |
| 동시 수정(Q1–2) | 안전한 자동 병합, 하이브리드 잠금, 실제 충돌의 A/B 비교와 수동 선택 | 서로 독립적인 변경인지 검증; 무조건 마지막 값으로 덮어쓰지 않기 |
| 오프라인(Q3) | 로컬 수정 보존, 재접속 때 자동/수동 병합과 별도 복구본 선택 | 로컬 작업은 서버가 승인한 공유 변경과 다름 |
| 프로젝트·에셋(Q4) | 변경사항 미리보기, 승인, 검증된 전송, 자동화 설정 | 서명·해시·GUID/.meta, 실행 코드, 라이선스, 기존 Active 보호 |
| Host·권한(Q5–7) | 예비 Host 사전 지정, 선택적 승계, 역할별 권한 | Host 운영권과 소유권은 별개. 분리된 네트워크에서 두 서버가 동시에 정본을 승인하면 안 됨 |
| Unity 전반(Q8–9) | 일반 Scene/Inspector/Prefab/Asset/Animation/Timeline과 장기적인 공동 Play Mode, 공식 MCP 연동 | 모든 Unity/외부 플러그인이 이미 지원된다는 약속이 아님 |
| 복구(Q10–12) | 작업 보존 최우선, 타임라인, 부분 복원, 미리보기와 별도 복사본 | 저장 파일·확정 수정·미확정 수정·백업은 서로 다름 |
| 사용성(Q13) | 초보자는 자동화된 간단한 경로, 전문가에게는 세부 설정 | 실제 초보자 테스트 전까지 UX 세부안은 확정하지 않음 |

**중요:** 사용자 의견은 달라질 수 있습니다. 여러 선택지를 지원한다는 것이 모든 정책을 동시에 실행한다는 뜻은 아닙니다. 안전한 기본 동작을 하나 정하고 필요한 고급 옵션만 제공하세요.

## 개발은 이 순서로

1. **P0 — 지금 있는 기능을 실제로 쓰게 만들기.** 겹치는 Draft #607/#614/#616을 무턱대고 합치지 말고 [통합 PR #620](https://github.com/Eun-si123/teamforge-unity-collab/pull/620)을 중심으로 검토. Unity 기본 생성·Inspector 조작·Host→Guest 참가와 두 물리 Windows Editor 테스트.
2. **P1 — M4와 M5의 일관된 버전 전환 완성.** 실시간 수정 확정·쓰기 중지·SQLite 체크포인트·서명된 새 프로젝트 파일·Guest Active 갱신을 장애에도 안전하게 연결. 현재의 SQLite 일괄 갱신 기반만으로 전체 기능이 완성된 것은 아님.
3. **P2 — M6~M8 실사용 확장.** 다중 Scene, 일반 Inspector, 외부 Prefab과 Asset, 그 뒤 Animation/Timeline/스크립트 등. 지원 범위를 정직하게 안내.
4. **P3 — 복구 타임라인·오프라인 병합.** 원본 보존, 충돌 미리보기, 필요한 부분만 복구, 격리된 복사본.
5. **P4 — 네트워크·역할·Host 승계.** 검증된 단일 Authority 유지, 수동 승계 우선, 이후 안전한 자동 승계·선택적 Relay와 2~8인 성능 측정.
6. **P5 — AI와 Play Mode 고도화.** 공식 Unity 도구의 정확한 버전·권한 확인 후 읽기 전용부터 시작. Play Mode 화면 관찰과 동일 게임 상태 공유를 구분.

기존 M1~M8을 폐기하지 않습니다. 위 P0~P5는 **사용자 가치와 검증 완료 기준**을 묶은 별도 층입니다.

## ‘실사용 가능’의 최소 조건

- Windows PC 두 대의 실제 Unity Editor에서 일반 Unity 메뉴로 만들고 수정한 지원 오브젝트가 정확히 같아야 합니다. 단순 연결 성공만으로 완료 처리하지 않습니다.
- 새 사용자가 도움 없이 Host 초대 → Guest 참가 → 프로젝트 수신·검증 → Unity 열기까지 진행할 수 있어야 합니다.
- 전송 실패·재접속·중복 메시지·충돌·저장 공간 부족·프로세스 강제 종료에서 **확정 작업을 조용히 잃거나 원본을 덮어쓰면 안 됩니다.**
- M4→M5 버전 전환은 이전 검증된 Active와 미확정 수정의 보존·복구를 포함해야 합니다.
- 2~8인 동작의 CPU/RAM/GC/네트워크/전파 지연은 TeamForge를 끈 기준선과 비교하고, 결과를 공개된 검증 기록과 연결해야 합니다.
- **소스 구현 / 자동 테스트 / 정확한 배포 ZIP / 물리 Windows 2대 / 독립 사용자 검증**을 서로 다른 증거 단계로 기록해야 합니다.

## 이미 있는 코드와 문서를 활용하세요

현재 구조인 Unity C# 패키지, Node Session Authority/Coordinator, Project Peer/Seed 직접 전송, 서명된 Project 검증, Windows Guest Launcher, M4 SQLite를 우선 재사용합니다. 새로운 동기화 엔진·복구 엔진·전송 프로토콜을 이유 없이 중복 구현하지 않습니다.

- [#620](https://github.com/Eun-si123/teamforge-unity-collab/pull/620): 통합 Draft, M4→M5 전환 기반. 구현 완료·실기기 검증은 아님.
- [#590](https://github.com/Eun-si123/teamforge-unity-collab/issues/590): 처음 사용 경험·구조 감사.
- [#598](https://github.com/Eun-si123/teamforge-unity-collab/issues/598), [#600](https://github.com/Eun-si123/teamforge-unity-collab/issues/600): Unity 기본 생성, 외부 에셋/Prefab.
- [#549](https://github.com/Eun-si123/teamforge-unity-collab/issues/549): 잠금과 충돌 정책.
- [#622](https://github.com/Eun-si123/teamforge-unity-collab/issues/622): 저사양 PC 성능.

공식 CLI/MCP를 사용하더라도 **AI 명령이 자동으로 TeamForge 권한 검사에 묶이는 것은 아닙니다.** 위험한 편집·스크립트 실행·권한 변경은 별도 제어와 검증이 필요합니다.

새로운 실기기 결과, 사용자 테스트, 데이터 손실 버그, 심각한 보안 문제, Unity 버전 변경이 나오면 이 결정 문서를 수정하세요. 목적은 처음 결정이 항상 옳다고 우기는 것이 아니라 **사용자에게 실제로 유용하고 안전한 제품으로 발전시키는 것**입니다.
