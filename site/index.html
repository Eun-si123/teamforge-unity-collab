Where the project stands now

TeamForge has working prototypes and automated source-level checks, but distribution and field validation intentionally come before promoting a public install path.

Available

Public source

Unity package, server, Project Peer, launcher, tests, architecture notes, and development reports are open for inspection.

Automated

Repository CI

Server, Project Peer, runtime-loader, and .NET Windows launcher checks run through GitHub Actions.

Stabilizing

Two-PC workflow

The intended Host → Guest → transfer → activation → realtime workflow still needs the exact field-validation gate closed before alpha distribution.

Not yet

General installable alpha

No packaged build is currently recommended to general users. A source Git URL is not being presented as a complete end-user release.

Enabled

Security automation

Automated dependency, secret, and code scanning support review, but they do not replace independent security analysis.

Not audited

Production trust

TeamForge has not completed an independent professional security audit and should still be tested with backups or disposable projects.

What TeamForge is exploring

TeamForge is not a replacement for Git or Unity Version Control. It focuses on the live, awkward moments around working closely together inside the Unity Editor.

Prototype

Presence & awareness

See who is connected and expose useful Editor context instead of collaborating blind.

Prototype

Transform sync

Synchronize supported Scene transform changes between connected Unity Editor instances.

Stabilizing

Hierarchy collaboration

Same-Scene create, delete, rename, reparent, and sibling-order synchronization exists in the experimental implementation.

Stabilizing

Locking & ownership

Reduce conflicting edits by making object ownership and editing intent visible and server-authoritative.

Stabilizing

P2P project bootstrap

Explore a lower-friction path for another developer to obtain the project state needed to join.

Stabilizing

Integrity & recovery

Resume, validation, diagnostics, and safe refusal paths are treated as core collaboration behavior.

Development history is part of the project.

TeamForge did not appear as a single finished code drop. The public repository keeps version milestones, phase documents, debugging notes, hotfix records, and technical decisions so the path from the first Editor connection prototype to the current stabilization work is easier to inspect.

0.1 → 0.2

Connection & Presence

The early releases established the Unity Editor connection foundation, diagnostics, identity, connected-user presence, selection, and Scene awareness.

0.3

Transform & Locking

Transform synchronization, server-authoritative revisions, late-join state, and basic locking moved the project from awareness toward shared editing.

0.4 → 0.4.1

Project bootstrap & stabilization

P2P project-transfer foundations, signed invites, integrity validation, Embedded UPM handling, retry/failover, and regression fixes were added and tested.

0.5

Hierarchy collaboration

Same-Scene create, delete, rename, reparent, ordering, authority, tombstones, and conflict handling expanded the collaboration surface.

Hotfixes

Field-driven fixes

Work-state and hotfix notes preserve many of the failures, investigations, and follow-up changes that happened between named releases.

0.5.1

Current stabilization

Bootstrap, networking boundaries, release-contract checks, and security-related validation continue to be tightened before a general public alpha.

Why TeamForge exists

The project started from a simpler question while I was building a Unity game with a friend: could two Unity Editor instances collaborate more directly inside the Editor itself?

That curiosity became an experiment in live Editor collaboration and project bootstrap, first as something I could try with a friend and then as a project that other friends, students, indie developers, and small teams could inspect, test, and potentially use.

한국어 소개

TeamForge는 Unity Editor에서의 실시간 협업을 실험하는 오픈소스 프로젝트입니다. 접속 상태, Transform 동기화, 같은 Scene의 Hierarchy 협업, 잠금/소유권, P2P 프로젝트 부트스트랩과 전송을 하나의 협업 흐름으로 연결하는 것을 목표로 합니다.

현재는 소스 공개 초기 프리뷰이며 일반 사용자용 설치 가능한 Alpha를 권장하는 단계가 아닙니다. 중요한 프로젝트에 사용하기 전에 현재 검증 상태와 제한사항을 확인해 주세요.

개발 과정도 공개되어 있습니다. 초기 연결 프로토타입부터 Presence, Transform/Lock, Project bootstrap, Hierarchy 동기화와 이후 Hotfix까지의 흐름은 변경 기록에서 볼 수 있고, 더 자세한 Phase 문서와 내부 작업 기록도 저장소에서 바로 확인할 수 있습니다.
